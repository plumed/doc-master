    V2.11

    Version 2.11 (under development)

    This page contains changes that will end up in 2.11

    Changes relevant for users:

    • New LINEAR flag for ABMD: the ratchet is applied to the distance from the target, V=K/2(d-d_m)^2, instead of the squared distance, V=K/2(d^2-d_m^2)^2. In this way the stiffness does not depend on the distance from the target and K has the units of an energy divided by the square of the CV. With LINEAR, MIN, NOISE and the _min components are distances. The checkpoint of ABMD records the flag and a restart with a different setting is an error.
    • New CHECKPOINT directive for an exact restart: PLUMED writes its own checkpoint file (one per replica, atomic write, previous one kept as _prev) when the MD engine writes its checkpoint (doCheckPoint signal, as in the GROMACS patches) or every STRIDE steps. The checkpoint stores the state of the actions at the start of the checkpointing step and the sizes of all the output files: at restart the files are truncated to those sizes (the lines written after the checkpoint by the interrupted run are removed, see #37) and the checkpointing step is computed again, which reproduces the uninterrupted run bitwise. The field header is not printed again at restart. Actions store their state with writeCheckpoint/readCheckpoint; those that have a state but do not store it yet are listed in a warning (MOVINGRESTRAINT is the first ported action). plumed checkpoint --dump prints a checkpoint file; driver has --checkpoint-stride (sends the signal like an MD engine) and --restart-from-checkpoint (presents the checkpointing step again, like GROMACS -cpi). METAD and PBMETAD store their full state (grid or hills, hill schedule, adaptive-hill statistics, work, acceleration, c(t), hills read from the other walkers): with CHECKPOINT the hills files are trimmed and not read at restart, and the first-hill rule is not needed. OPES_METAD and OPES_METAD_EXPLORE store their full state (kernels, normalization, weights, adaptive sigma, neighbor list): with CHECKPOINT the KERNELS file is trimmed and neither it nor STATE_RFILE is read at restart. METAINFERENCE and the ISDB collective variables with DOSCORE store the Monte Carlo state (sigma, scale, offset, ftilde, the three random number generators, acceptance counters, weights, sigma-mean histories), EDS its couplings, running statistics and random generator, DRR the fictitious particles, the ABF and CZAR grids and the thermostat (the umbrella integration estimator is not stored): with CHECKPOINT the status, restart and .drrstate files are not read at restart. ABMD stores the running minimum and the white-noise generators, EXTENDED_LAGRANGIAN the fictitious positions and velocities and the Langevin generator, and ACCUMULATE and COLLECT the accumulated or collected data (grids, vectors and matrices, with their shape), so that averages, histograms and time series continue exactly. COMMITTOR stores the basin, MAXENT the Lagrangian multipliers, their averages and works (the LAGMULT file is not read), READ the position in the file, RANDOM_EXCHANGES the state of the generator of the exchanges, and EFFECTIVE_ENERGY_DRIFT the drift and the data of the previous step (with more processes the data of all of them is gathered in the checkpoint and redistributed at restart, also to a different number of processes; the restart is then exact up to the rounding of the sum over the processes). LOGMFD stores the fictitious variables, velocities, forces, thermostat variables and works (and cuts its plain logmfd.out and replica.out files at the checkpoint size), FISST the weights, partition estimates and averaged forces, RESCALE the bias, Monte Carlo state and selector, EMMI sigma, the Monte Carlo state, the regression scale and the average weights, and EMMIVOX scale, offset and Bfactors with their Monte Carlo state. The neighbor lists of EMMI and EMMIVOX are rebuilt at the first step. The per-step files of the model overlap/density of EMMI and EMMIVOX are no longer appended to when they exist (they are renamed as a backup). VES biases and optimizers, ADAPTIVE_PATH, the maze actions and TTMETAD keep an internal state that is not stored yet: they are listed in the warning.
    • When using MOLINFO with the WHOLE flag, PBCs in the following actions will be reconstructed using a minimum spanning tree based on the coordinates stored in the MOLFILE reference pdb.
    • When the reference pdb of MOLINFO with the WHOLE flag has a CRYST1 record with space group P 1, PLUMED now checks along each chain that the reference is whole in that box, and writes a warning to the log naming the atoms that are across the periodic boundary from the atom before them. Before, a split reference made WHOLEMOLECULES split whole molecules without any warning.

    • Updated the embedded Lepton and AsmJit libraries from OpenMM 8.6.1, preserving PLUMED-specific expression functions and semantics. Just-in-time compilation of CUSTOM expressions and custom switching functions now supports AArch64, including Apple Silicon, and is enabled by default on supported architectures. It can be disabled with ./configure --disable-asmjit or at runtime with PLUMED_USE_ASMJIT=no.

    • When using MOLINFO with the WHOLE flag, PBCs in the following actions will be reconstructed using a minimum spanning tree based on the coordinates stored in the MOLINFO reference PDB. Fixed the tree construction and parent/child indexing in this reconstruction: previously actions such as CENTER, RMSD, and GYRATION could silently use split coordinates (see #1496).

    • When using the benchmark now it is possible to scale the atom distances in the synthetic atom distribution (the base atomic distance is 1)
    • SAXS now accepts the MARTINI_FF keyword to select the Martini form-factor generation: MARTINI_FF=2 (default) keeps the existing Martini 2.2 protein and nucleic-acid form factors, while MARTINI_FF=3 selects Martini 3 protein form factors.
    • SAXS includes bug fixes related to the ONEBEAD approach and nucleic acid in some corner case, as well as general improvements in performances and SANS calculation.
    • SAXS includes new ions parameters that can be used both in ATOMISTIC and ONEBEAD modes.
    • SAXS and SANS: the ArrayFire implementation (GPU flag) has been removed. The Debye sum can now be computed on the GPU with the USEGPU flag, using a backend provided by a plugin (plugins/openaccPTM, OpenACC). With MPI each rank computes a share of the sum on its own GPU. On an A100 the sum is 20-40 times faster than on 32 CPU cores (see the README of the plugin).
    • Residue numbers in the pdb files read by MOLINFO and by the TEMPLATE of SAXS, as well as in the CS2BACKBONE and EMMIVOX inputs, can be negative (e.g. tags in protein constructs, see #1089). Negative residues can be selected with e.g. @phi--3, @phi-A-3 or @phi-A_-3 and in ranges such as RESIDUES=-10--1 or RESIDUES=-5-10. Previously negative residue numbers were silently converted to very large positive numbers. RESIDUES=all (e.g. in ALPHARMSD) and the ONEBEAD mapping of SAXS now only use the residues present in the pdb file, so they also work when the numbering has gaps.
    • Fixed RESIDUES=all in ALPHARMSD, ANTIBETARMSD, PARABETARMSD and WHOLEMOLECULES when the pdb file of MOLINFO contains chains that use the same residue numbers (e.g. all chains starting from residue 1): the backbone atoms of all the chains were taken from the first chain. With an explicit list of residues (e.g. RESIDUES=2-10), residue numbers present in more than one chain are still taken from the first chain, and a warning is printed.
    • METAINFERENCE includes stability fixes when restarting while parameter optimisation is running.
    • Added environment variable PLUMED_LOG_FILE to control the log file pathname when running with GROMACS (the log file was hardcoded as PLUMED.OUT)
    • Changed CUTOFF keyword in DISTANCE_MATRIX to LINKCELL_CUTOFF to make the purpose of this keyword clearer.
    • The kernels of OPES_METAD and OPES_METAD_EXPLORE are now force-shifted at KERNEL_CUTOFF, so that both their value and their derivative go to zero at the cutoff. Previously they were energy-shifted: their value went to zero at the cutoff, but their derivative jumped to zero there (see #1463). Bias values and kernel heights change only in the far tails of the kernels, and forces change slightly, mostly early in a simulation. The script FES_from_State.py of the OPES tutorial uses the new kernels.
    • OPES_METAD and OPES_METAD_EXPLORE now use their neighbor list by default, since it is exact and never slower; it can be switched off with NLIST_OFF. The NLIST flag is still accepted, and only adds the nlker and nlsteps components as in previous versions. The NLIST_PACE_RESET flag is removed: with WALKERS_MPI, the neighbor list is now always reset after each deposition.
    • In KDE, HISTOGRAM, RDF and PAIRENTROPY you can now use the switching function syntax detailed in LESS_THAN to set up the parameters for the kernel to use in kernel density estimation. The default kernel that is used in these actions has changed. In the new version of the code the kernel is a Gaussian that has been stretched and scaled to ensure that it is zero for all values greater than the cutoff. In other words, the default behaviour in these methods is now the same as the behavior used for sum_hils and METAD.
    • Positions and forces are shared with the MD code faster. The lists of the atoms needed by the actions are rebuilt only when they change, also when an MD code with domain decomposition passes the same local atoms at every step; the choice between copying all the atoms and copying only those that are needed (PLUMED_FORCE_UNIQUE=auto) is based on all the atoms needed by the active actions instead of on the largest single action; OpenMP threads are only used for large copies. With plumed benchmark, 7000 atoms and three COORDINATION between one atom and 2207 atoms, "Sharing data" went from 82 to 7 microseconds per step in serial and from 84 to 25 microseconds with domain decomposition on two ranks.
    • Actions with a neighbor list (e.g. COORDINATION with NLIST) request the reduced list of atoms only once after each update of the list, instead of at every step: requesting the same atoms made PLUMED rebuild the lists of atoms at every step.
    • FIT_TO_TEMPLATE and RESET_CELL, which move all the atoms, are 2 to 5 times faster: they loop directly on the arrays of positions and forces. With plumed benchmark, 7000 atoms and TYPE=OPTIMAL with 200 aligned atoms, FIT_TO_TEMPLATE went from 148 to 90 microseconds per step for the positions and from 260 to 48 for the forces. The results are identical.
    • The forces on the eigenvectors computed by DIAGONALIZE (used e.g. when biasing SPRINT) are computed in a time that scales as N^2 instead of N^4 with the size N of the matrix. With a 200x200 contact matrix, applying the forces went from 5 seconds to 0.3 milliseconds per step.
    • The iterations of the SMACOF algorithm (used by ARRANGE_POINTS with MINTYPE=smacof and by SKETCHMAP with USE_SMACOF) scale as M^2 instead of M^3 with the number of points M: with 1000 points an iteration went from 3 seconds to 6 milliseconds.
    • Symmetric positive definite matrices (e.g. the covariance matrices of multivariate Gaussians) are inverted with a Cholesky factorization instead of being diagonalized, which is 5 to 25 times faster for matrices with up to 10 rows and about 4 times faster for large matrices; matrix products are 2 to 5 times faster. METAD with ADAPTIVE=DIFF and three CVs depositing a Gaussian at every step is about 20% faster, and reading 20000 multivariate Gaussians when restarting is about 25% faster.
    • When no derivatives are needed, DIAGONALIZE computes only the requested eigenvalues and eigenvectors (from the largest one down to the smallest requested one) instead of all of them. With VECTORS=1 this is 3 to 4 times faster: e.g. for a 1000x1000 contact matrix it went from 180 to 70 milliseconds per frame. CLASSICAL_MDS also benefits: with 2000 frames the analysis is about 20% faster. The results are identical.
    • PLUMED stops with an error, instead of crashing, when it has to apply forces on the atoms or on a value passed with PUT and the MD code did not pass the array for these forces. The size of the arrays passed with domain decomposition is now checked also when PLUMED is compiled without debug flags.
    • METAD and PBMETAD have been revised; PBMETAD now uses the grids, kernels and hills files of METAD. Results change in the following cases:
      • Grids are extended automatically when a Gaussian does not fit in them (GRID_MIN and GRID_MAX give the initial range; GRID_SIZE_LIMIT sets the maximum number of points); GRID_SPACING can be given without GRID_MIN and GRID_MAX. A grid read with GRID_RFILE(S) can have any range on the lattice of the grid in input.
      • No Gaussian is added at the first step of a simulation; when continuing a simulation, a Gaussian is added at the first step unless the hills file already contains it (also when restarting from a grid, see #267). PBMETAD never added a Gaussian at the first step of a run.
      • ADAPTIVE=DIFF: when restarting, the statistics of the fluctuations are initialized from the last hills of the hills file (DIFF_FROM_SCRATCH restores the old behavior); with replica exchange the running average is restarted when an exchange is accepted, instead of stopping with an error (#26); PRECAL_DIFF accumulates the statistics also outside the update window (#1328).
      • An incomplete last line of the hills file (an interrupted run) is removed when restarting (#727).
      • PBMETAD uses stretched Gaussians, as METAD and as written in its hills files (biases change by about 0.2%); it requires the temperature (TEMP); partitioned families with ADAPTIVE and families in a different order than the arguments are fixed.
      • INTERVAL with a grid: beyond the limits the force is zero also within the grid cell that contains a limit; with NLIST the neighbor list is built at the limit.
      • Multiple walkers: the hills files are read by the first MPI process of each walker and broadcast (with several processes per walker the run could hang); restarting from the grid of a walker (WALKERS_N) adds only the hills of the other walkers that are not in the grid (their number is written in a comment after the grid); the hills and grid files are read without the replica suffix, as they are written.
      • Grids are filled with OpenMP and are faster also without OpenMP; the c(t) reweighting factor (CALC_RCT) is fixed with GRID_SPARSE; ACCELERATION and FREQUENCY_ADAPTIVE are restarted correctly.
      • PBMETAD: BIASFACTOR=1 means, as in METAD, that no bias is applied and the hills files and grids contain the estimate of -F (TAU can be given instead of HEIGHT); new PRECAL_DIFF and STORE_GRIDS keywords, as in METAD.
      • Inputs that crashed or gave meaningless results are now errors (e.g. WALKERS_RSTRIDE=0, negative SIGMA, HEIGHT or TAU, ADAPTIVE on a grid without SIGMA_MIN also in PBMETAD and when reading a grid in METAD, a SELECTOR that is not defined in PBMETAD).
    • sum_hills has been revised:
      • variables whose name contains sigma_, time, min_ or max_ are found correctly (they made it crash, #1226); --spacing can be used without --min and --max; --negbias is correct also when the run was not well tempered; with MPI the derivatives were zero.
      • --sort time (or clock) merges the hills files of multiple walkers in order of time, so that the free energies written with --stride follow the simulation (#1351).
      • --average computes the time average of the bias, and --basins writes the free-energy differences between basins at each output, to check convergence.
      • The hills are summed several times faster (the Gaussians are computed as products over the variables), and with MPI the grids are summed once per output.
      • The documentation has been rewritten. It now states that --histo does not reweight the points, and shows how to compute a free energy from a biased simulation with driver, REWEIGHT_BIAS and HISTOGRAM.
    • The examples in the documentation of HISTOGRAM, REWEIGHT_BIAS, REWEIGHT_METAD and METAD that use LOGWEIGHTS now set NORMALIZATION, without which HISTOGRAM stops with an error.
    • METAINFERENCE and the ISDB collective variables with DOSCORE (NOE, PRE, RDC, JCOUPLING, CS2BACKBONE, SAXS) now share one implementation of Metainference. Results change in the following cases:
      • New SEED keyword to make the Monte Carlo sampling of the uncertainties, scale, offset and ftilde reproducible (by default the seed is still taken from the clock).
      • SELECTOR and NSELECT were ignored by the collective variables with DOSCORE (the history of sigma mean and the averaged weights were always those of the first selector value); they now work as in METAINFERENCE.
      • With DOSCORE and RESTART, a missing status file was created empty and then read as a restart (averaged weights starting from zero); it is now a new start, as in METAINFERENCE.
      • NOISETYPE=GENERIC could not be restarted (ftilde was not read back from the status file).
      • OPTSIGMAMEAN with a single replica gave NaN after AVERAGING steps: the standard error of the mean is not defined with one replica, and sigma mean now keeps its initial value.
      • Monte Carlo moves larger than the allowed interval (DSIGMA, DSCALE or DOFFSET larger than the range of the flat prior) could leave the interval; with NOISETYPE=GENERIC and OPTSIGMAMEAN, sigma could move above SIGMA_MAX when sigma mean exceeded it (it is now kept equal to sigma mean, with a warning).
      • More than one DSIGMA with NOISETYPE=GAUSS or OUTLIERS is an error, as for SIGMA0, SIGMA_MIN and SIGMA_MAX.
      • Moves of chunks of sigmas (MC_CHUNKSIZE) and of ftilde are computed from energy differences, and the history of sigma mean (OPTSIGMAMEAN with AVERAGING) no longer grows in cost with AVERAGING. NOE, PRE, RDC and JCOUPLING no longer look up their components by name at every step (with 3000 NOEs and DOSCORE a step went from 24 to 1.7 ms).

    • Bug fixes and performance improvements in the other ISDB actions. Results change in the following cases:

      • CALIBER: with SCALE different from 1 or with REGRES_ZERO the forces were not the derivatives of the bias (they were divided instead of multiplied by the scale). The data file is checked (it was read with a duplicated last line), its first time is no longer assumed to be zero, and a simulation time outside the data is an error.
      • CS2BACKBONE: the non-bonded term excluded the residues adjacent in sequence without looking at the chain, so with chains numbered from 1 the contacts between residues with close numbers in different chains were dropped. ATOMS and TEMPLATE must now contain the same atoms (they were silently assumed to be numbered from 1 in the same order). With MPI less data are communicated.
      • EMMI: with REWEIGHT the forces and the derivative with respect to the bias were wrong when the weights of the replicas were different; atoms with the same tabulated overlap could be dropped from the neighbor list. New SEED keyword. With MPI the derivatives of the overlaps are no longer summed at every step; OpenMP parallelization; the scale regression is done once instead of on every rank and replica.
      • EMMIVOX: new SEED keyword; the neighbor sphere uses a cell list (it was O(voxels x atoms)); results no longer depend on the number of OpenMP threads; the score is summed in double precision.
      • SAXS and SANS: faster Debye sums (sine and cosine for all the q values by angle addition), with DOSCORE only the contracted derivatives are summed over the MPI ranks, faster SASA for ONEBEAD. Without DOSCORE the derivatives of the intensities (with respect to all the atoms with ONEBEAD) are stored with OpenMP threads, and the forces on the components of the ISDB collective variables are applied with OpenMP threads. With SIGMARES the self term of the intensity is now smeared too. The random deuteration of SANS is drawn by the first rank with PLUMED's own generator.
      • JCOUPLING with DOSCORE now sets the j-# components (they were always zero); RDC with DOSCORE no longer allocates derivatives for each coupling.
      • RESCALE uses PLUMED's random number generator and has a SEED keyword; SELECT and RESCALE stop if the SELECTOR does not exist; SHADOW checks that exactly one replica uses REFERENCE; BAIES checks that the atoms in DATA_FILE are in ATOMS.

    • JCOUPLING with TYPE=CUSTOM used uninitialised Karplus parameters when A, B or C were not given; A, B and C are now compulsory with TYPE=CUSTOM, and SHIFT is zero by default.

    • UPPER_WALLS and LOWER_WALLS acting on periodic arguments do not apply periodic boundary conditions to the difference between the argument and AT anymore (#658). Previously each wall acted on half of the periodic domain, so that e.g. an upper and a lower wall at on a torsion pushed it out of the interval when its value was beyond . AT must now be within the periodic domain of the argument. Results are unchanged when the argument stays further than half a period from AT.

    • MOLINFO selectors based on a python interpreter (@mda:, @mdt:, @vmd: and @vmdexec:) now terminate the interpreter, and the processes it starts (e.g. vmd), when PLUMED finishes. Previously only the shell used to launch the interpreter was signaled, so that the temporary file created by the selector script could be left behind and processes that did not exit when their input was closed could be left running.

    • Fixes and speed-ups in the biases (src/bias):

      • A bias that does not set the force on an argument at a step now applies no force to it. Before, the force of the last step in which it was set was applied again: MOVINGRESTRAINT with VERSE=U or VERSE=L pushed the argument while it was on the side where the restraint does not act (with zero bias, and with a wrong work); ABMD pushed the argument while it was moving closer to the target than ever before; VES_LINEAR_EXPANSION pushed the argument when it was outside the range of the basis functions.
      • RESTRAINT: with scalar arguments, SLOPE was ignored when its first value was written as 0.0 (e.g. SLOPE=0.0,2.0). With vector arguments, KAPPA=0 for the first argument and a non-zero value for another one gave an input error, and force2 was instead of .
      • UPPER_WALLS and LOWER_WALLS acting on vectors gave nan with a non-integer EXP. They are also faster: with 20000 distances, an upper and a lower wall cost 2.3 instead of 8.5 milliseconds per step. RESTRAINT on a non-periodic vector uses one action less per argument (with 20000 distances, KAPPA and SLOPE: 2.6 instead of 4.1 milliseconds per step).
      • MAXENT: with ERROR_TYPE=LAPLACE the Lagrangian multipliers were never kept within the range allowed by the prior; the average between TSTART and TEND was too large by one term when an update happened exactly at TEND; the _error components were always zero; an unknown TYPE or ERROR_TYPE is now an error (it gave no bias).
      • Biases stop with an error when an argument is a vector with more than one element (only its first element was used, e.g. by BIASVALUE).
      • Input errors instead of crashes or meaningless results: MOVINGRESTRAINT without STEP0, KAPPA0 or AT0, or with a VERSE other than U, L, B; EXTENDED_LAGRANGIAN with non-positive KAPPA or TAU or negative FRICTION; REWEIGHT_TEMP_PRESS with REWEIGHT_TEMP=0.

    • Fixes and speed-ups in the tools used by many actions:

      • Neighbor lists of COORDINATION and similar variables with a single group of more than 32768 atoms (GROUPA only, with NLIST) contained wrong pairs and could crash (32-bit overflow).
      • With NLISTCELLS and NOPBC, the cells were built on the periodic box and close pairs on the two sides of the planes at half box were missed. NLISTCELLS now also keeps only the pairs within NL_CUTOFF, as NLIST does (the list contained all the pairs of neighboring cells, about 6 times more), and it is parallelized with MPI and OpenMP (with 20000 atoms and a list updated every 5 steps, 4.7 times faster in serial).
      • Neighbor lists built with several OpenMP threads have the pairs in the same order as in serial: before, the order depended on the timing of the threads, so that two runs with the same input could give slightly different results.
      • Link cells (used by NLISTCELLS, CONTACT_MATRIX and the other adjacency matrices) are built on every process without MPI communication, and their number is limited.
      • Shuffling (used by METAINFERENCE with MC_CHUNKSIZE to choose the uncertainties that are moved) only produced cyclic permutations, so that the choice was not uniform (e.g. with two uncertainties, one step and chunks of one, the first uncertainty was never moved).
      • Text files (e.g. hills files, grids, colvar files) are read in chunks instead of one character at a time, and numbers are converted with std::from_chars (when available) instead of a string stream: sum_hills on 300000 hills went from 9.8 to 2.5 seconds.
      • nan, inf and -inf, as written by PLUMED in its output files, are read correctly; negative numbers are not accepted anymore where an unsigned integer is expected (e.g. STRIDE=-1 was read as 4294967295).
      • Output files are written without two MPI collective operations per line, and with MPI they are opened only by the first process (the other processes open /dev/null): opening and truncating the same file from all the processes is slow on parallel file systems.
      • In single precision (e.g. the OpenACC implementation of DISTANCE), periodic boundary conditions in triclinic boxes were applied with an error up to 4e-6 times the box size; they are now exact.
      • Values outside a grid on its lower side give an error on all architectures (on arm64, e.g. Apple Silicon, they gave the value of the first bin).
      • A CUSTOM switching function with a constant derivative (e.g. SWITCH={CUSTOM FUNC=1-x R_0=1}) stopped with "getVariableReference: Unknown variable".

    • Fixes and speed-ups in the core of PLUMED:

      • Less overhead per action and per step: OpenMP threads are used to clear the derivatives and to sum the forces of an action only when there is enough work. Before, two OpenMP regions were opened for every action at every step, which was expensive when PLUMED runs with several threads (e.g. GROMACS passes its number of OpenMP threads to PLUMED). With plumed benchmark, 400 atoms, 200 DISTANCE and 200 RESTRAINT, a step went from 226 to 85 microseconds with one thread and from 513 to 85 microseconds with two threads.
      • Forces on virtual atoms (CENTER, COM, ...) are applied 3 times faster: they were computed twice.
      • Reading an input with many actions is much faster (the time grew quadratically with the number of actions): 8000 DISTANCE lines are read in 0.4 seconds instead of 17.5.
      • Forces on the elements of a sparse matrix that is not square (e.g. CONTACT_MATRIX with GROUPA, GROUPB and a cutoff) passed through FLATTEN were added to the wrong elements, and a linear function of a flattened sparse matrix (e.g. its SUM) stopped with an error.
      • UPDATE_IF ARG=... END without a matching opening UPDATE_IF is now an input error (it led to undefined behavior).
      • With replica exchange through the GREX interface (e.g. Hamiltonian replica exchange with GROMACS), PLUMED stops with an error if the two replicas exchange states of different size, instead of reading a truncated state.
      • The labels of the detailed timers (DEBUG DETAILED_TIMERS) were shifted after the actions that are computed during the update step.
      • The type of the arguments (scalar, vector, matrix, function on a grid) is checked against the types accepted by the action: the check always passed, so that e.g. a vector given to RESTRAINT_SCALAR or MOVINGRESTRAINT was silently biased through its first element only. The error message lists the accepted types.
      • The set up of shortcuts that create an action with many numbered keywords is not quadratic anymore, e.g. DISTANCES with GROUPA and GROUPB with 300k pairs of atoms takes 1.4 s instead of 94 s (ActionShortcut::addToSavedInputLines).
    • Fixes in the command line tools:
      • driver: the single precision version (driver-float, or --debug-float yes) stopped at the first frame; a trajectory file that cannot be opened made driver and benchmark crash; reading xtc, trr and molfile trajectories from standard input is now an error (it was a crash); clear errors for a wrong --box, an atom index out of range in the --mc file and a --dump-forces file that cannot be opened.
      • simplemd: the forces were wrong when sigma is not 1; with temperature NVE (the default) the initial velocities and the thermostat used uninitialized values (now the atoms start at rest and there is no thermostat); nconfig and nstat without a file name used a random file name (the defaults are now 10 trajectory.xyz and 1 energies.dat). The neighbor list is built with linked cells when the box is large enough (with 4096 atoms a run is 6 times faster, with identical results), and results with OpenMP no longer depend on the timing of the threads.
      • pesmd: temperature NVE used uninitialized values; the energy of the thermostat in stats.out was wrong with more than three dimensions; the final jobs were not run (e.g. a DUMPGRID with STRIDE=0 wrote nothing). The friction keyword is the relaxation time of the thermostat (as before; the documentation said friction).
      • plotswitch never ended with --centerrange; the table is written on the output of the tool and its points pass through R_0.
      • pdbrenumber: with several models, the numbering restarted from 0 after each ENDMDL instead of from the first number.
      • Tools reading an input file (e.g. simplemd, pesmd): a flag missing from the file made them crash, lines longer than 255 characters were split, and an unknown keyword gave exit code 0. Errors in the input of a tool now give a message and exit code 1 instead of an abort.
      • benchmark with --domain-decomposition stopped with an error when run with plumed --no-mpi in a build with MPI. With --shuffled or --domain-decomposition the positions were not moved with the atoms, so that PLUMED saw a different, permuted structure (which also depended on the C++ library, since std::shuffle is implementation defined).
      • Smaller fixes in gen_example, gen_json and show_graph.
    • COMBINE has a new CIRCULAR flag to combine periodic arguments as angles: the output is the argument of (with the default coefficients, the circular mean of the arguments), scaled to the domain given with PERIODIC (#164).

    • Bug fixes in the functions. Results change in the following cases:

      • Elements of a vector whose arguments are all zero (e.g. the output of LESS_THAN with a D_MAX, or of a CONTACT_MATRIX row sum) were set to zero without evaluating the function, which is wrong when the function is not zero there: e.g. CUSTOM with FUNC=x+1, COMBINE with PARAMETERS, LESS_THAN and BETWEEN around zero. For example, COORDINATIONNUMBER with LESS_THAN did not count the atoms with no neighbors within D_MAX.
      • CUSTOM set the function to zero when an argument that is zero (with zero derivative) appeared in a product anywhere in the expression, e.g. FUNC=x*cos(y)+1 or FUNC=exp(x)*y. Only the arguments that multiply the whole expression are now used for this.
      • Forces were lost when SORT, MOMENTS, HIGHEST or LOWEST take a single vector or matrix in input and only components other than the first are biased (e.g. sort.4, m.moment-3), and they were applied to the wrong elements of a sparse matrix.
      • MOMENTS of periodic variables were wrong (the circular mean was shifted by half a period); the derivative of the circular mean is now included.
      • PRODUCT, and thus DETERMINANT, gave nan for negative values (it was computed as the exponential of a sum of logarithms) and did not accept periodic scalars.
      • FUNCPATHMSD and FUNCPATHGENERAL no longer underflow far from the path (FUNCPATHMSD gave nan); FUNCPATHMSD accepts DISTANCE arguments again; NEIGH_SIZE requires a positive NEIGH_STRIDE.
      • The documentation of BESSEL now states that it computes the exponentially scaled function .

    • Fixes and speed-ups in the generic actions:

      • PDB2CONSTANT and READMASSCHARGE kept only 6 significant digits of the values they read (reference positions and arguments, masses and charges). This affected the actions that read their reference through PDB2CONSTANT (RMSD, PATH, GPATH, ADAPTIVE_PATH, PCAVARS, ...): with a large LAMBDA, PATH and PATHMSD on the same reference differed by 1e-4; they now agree.
      • DUMPATOMS in xtc or trr format: with MPI, all the processes wrote the file; with RESTART the frames were appended several times and the file was corrupted.
      • DUMPPROJECTIONS ignored RESTART and FLUSH, was written by all MPI processes, and multiple replicas wrote the same file.
      • EFFECTIVE_ENERGY_DRIFT was wrong with MD codes that reorder their atoms in serial runs (e.g. LAMMPS); with domain decomposition (e.g. GROMACS) the positions and forces of all the atoms were gathered on all the processes at every step, now only when the atoms move to another process.
      • FIT_TO_TEMPLATE with an unknown TYPE did not align anything; it is now an error. With TYPE=OPTIMAL and a reference whose beta column is all zero (the beta column only weights the RMSD that FIT_TO_TEMPLATE returns, not the alignment), this RMSD was nan; it is now zero, and the alignment is unchanged.
      • FISST crashed (division by zero) at the first step when OUT_OBSERVABLE was not used; PERIOD=0 is now an error.
      • WRAPAROUND is faster (about 30% with an orthorhombic box), with identical results.
      • Errors instead of crashes or undefined behavior for COMMITTOR without basins, CREATE_MASK with TYPE=stride NZEROS=0, DUMPPDB without ARG and ATOMS; DUMPPDB with ATOMS does not replace the names given with ARG_NAMES anymore. UNITS prints the Boltzmann constant in the new units.

    • Bug fixes in the secondary structure collective variables (ALPHARMSD, ANTIBETARMSD, PARABETARMSD, SECONDARY_STRUCTURE_RMSD and SECONDARY_STRUCTURE_DRMSD):

      • the two strands of a sheet were made whole together as a single chain, so the value of ANTIBETARMSD and PARABETARMSD changed when a strand was wrapped by the periodic boundary conditions (it is again as in 2.9); with NOPBC the periodic boundary conditions are now not used at all, also for the STRANDS_CUTOFF distance;
      • the default R_0 of the three shortcuts is 0.08 nm in whatever length unit is set with UNITS (it was 0.08 in the units of the input, i.e. 10 times smaller than intended with UNITS LENGTH=A, which gave almost no helix, beta etc.);
      • segments that do not contain 30 atoms (e.g. three atoms) read and wrote out of bounds and crashed; segments from 2 to 30 atoms are now supported and wrong input (different sizes of the segments, indices outside ATOMS, wrong size of STRUCTURE, missing STRUCTURE, ALIGN_STRANDS without 30 atoms, empty RESIDUES) is an error;
      • SECONDARY_STRUCTURE_DRMSD read out of bounds when scaling the derivatives, returned nan forces when a segment had distance zero from its reference, and did not give an error when all the distances in the reference were shorter than BONDLENGTH; the examples in its documentation had no BONDLENGTH and did not use Angstrom as the STRUCTURE unit;
      • ANTIBETARMSD and PARABETARMSD with STYLE=inter crashed when a chain contained a single residue; they are now an error only when no pair of strands can be built.

    • Fixes in the collective variables:

      • DIHEDRAL_CORRELATION with ATOMS (a single variable) crashed: the atoms were never requested.
      • CHARGE returned the masses of the atoms instead of their charges, and an error is given when the MD code does not provide the charges.
      • RMSD with DISPLACEMENT and TYPE=OPTIMAL (or TYPE=OPTIMAL-FAST) on a reference with more than one frame: the forces on the distances (.dist) were zero.
      • PATHMSD with NEIGH_STRIDE=0 crashed with a floating point exception, and LAMBDA=0 gave nan; they are now errors, as is using only one of NEIGH_SIZE and NEIGH_STRIDE.
      • CONTACTMAP with a single contact and CMDIST failed saying that REFERENCE was missing even if it was given; REFERENCE is now applied to all the contacts. No contacts is an error.
      • GHBFIX: the pairs of types in the PARAMS file that are not in the TYPES table were assigned to the first type, so that they could overwrite the parameters of that type depending on their order in the file. They are now skipped (their number is written in the log). The parameters (D_0, D_MAX, C), the types and the atom indexes are checked, and unknown keywords are not silently ignored.
      • EEFSOLV with TEMP_CORRECTION had no effect because of a wrong condition. The heat capacity term was also in the wrong units (cal/mol/K used as kcal/mol/K) and had the wrong sign with respect to Lazaridis and Karplus: the correction is now zero at 298.15 K and, as expected, makes the solvation free energy less favourable at higher temperature. Results with TEMP_CORRECTION change (they were identical to those without the flag).
      • ERMSD ignored NOPBC (the molecule was always made whole) and did not check the residue indexes in PAIRS.

      • DIMER checks that DSIGMA is consistent with the number of replicas before using it; GYRATION without atoms is an error; the RMSD shortcut closes the reference file after counting its frames.
      • Variables that use MultiColvarTemplate with single precision no longer require charges when they do not use them.
      • GHBFIX is about 7% faster (the cutoff is tested before looking up the types of the atoms), with identical results; COORDINATION and the variables that share its implementation do not allocate the per-thread buffers of the derivatives when running on a single thread.

    • Fixes in the virtual atoms (src/vatom):

      • CENTER and COM with PHASES (also SAFE_PHASES, when it uses the fast implementation) applied wrong forces to the atoms in non-orthorhombic cells, because the derivatives were transposed. Cubic and orthorhombic cells were not affected.       • GHOST stops with an error, instead of giving nan, when the first two atoms coincide or the three atoms are collinear.

      • ARGS2VATOM: the checks on the arguments now reject vectors and empty lists (they were skipped because of a wrong logical operator).

      • COORD_ANGLES (and ANGLES with SWITCH) with more than one central atom also included the angles between bonds that start from different atoms.       • The files generated by running plumed (vim/syntax, vim/help, json/syntax.json) are regenerated only when the plumed executable changes.
      • With make -j, the python interface is now built concurrently with the C++ code, and the libraries in src/lib and in src/lib/install are linked concurrently.
      • The python interface is compiled from the committed python/plumed.c, so building it does not require cython and does not modify tracked files anymore. plumed.c is regenerated from plumed.pyx and cplumed.pxd only when they change (or with make -C python cythonize), and must then be committed; its consistency is checked in the CI.
    • Subprocess launches the command in a new process group and sends the signals to the whole group, so that they also reach the processes started by the shell. Subprocess::stop() and Subprocess::cont() (enabled with PLUMED_ENABLE_SIGNALS) now actually stop and resume these processes. When a Subprocess is destroyed, the group receives SIGTERM (and SIGCONT, in case it was stopped) and, if the shell has not exited after one second, SIGKILL.
    • The xdrfile and molfile modules are now always compiled: since the trajectory parser was moved to src/tools it requires them, and configuring with --enable-modules=none (or removing one of them) failed at link time.
    • The core module does not call blas directly anymore: the only call (a daxpy used to sum the forces in ActionWithValue) has been replaced by a plain loop, which is as fast and avoids calling a threaded blas within an OpenMP region. The configure warnings printed when the internal blas/lapack are used have been reworded, since the internal versions are only slower than an optimized external library with large matrices.
    • pseudoInvert builds the pseudoinverse with a single product, without the intermediate dense matrices; the result is the same and it is up to 2 times faster for large matrices. diagMatRange computes only a range of the eigenvalues and eigenvectors of a symmetric matrix.
    • The inputlines now are parsed using a dictionary instead of an array. This speeds up the parsing of massive input lines.
    • Abstracted the AtomDistribution functionality from the benchmark. It can be used in tests or in other
    • It is not possible anymore to register lowercase keywords and the developer must always specify the keywords completely as uppercase while parsing in the action constructor. There are no differences for the user, apart the entry in the manual for the DEBUG action: the user can still specify lowercase and mixed case keywords in the input file.
    • Some improvements in the management of the plugins:
      • Now the plugins have a common directory structure
      • The plugins now are checked with codechek.
      • The plugins now will be formatted with the astyle target in the main directory
      • The plugins will NOT be cleaned with the clean command from the main directory
    • With --enable-rpath, if the linker writes RPATH by default (older toolchains), configure now adds -Wl,--enable-new-dtags so that RUNPATH is used. With RPATH the executables of the build tree loaded the kernel installed in the target directory (if any) instead of their own one, even after sourcing sourceme.sh: for instance the build failed with unknown command gen_vim when an older version was installed there.
    • Removed the optional --enable-boost_graph configure option and the __PLUMED_HAS_BOOST_GRAPH macro. The Boost branch of DFSCLUSTERING was disabled by default, no longer compiled against the current code, and not tested in the CI; the built-in depth first search is now always used.
    • Added a new python workflow in the CI for checking the python interface and the pycv plugin with multiple python versions
    • Part of the python scripts are now checked for errors and for formattation in the CI.
      • The formattation and the checking of the code are made with the ruff python package
      • The astyle target in the main Makefile will attempt to format the python scripts if finds ruff
    • Python packaging:
      • python/pyproject.toml and python/build_backend.py (a PEP 517 backend wrapping setuptools) build the wheels with the bundled kernel, using configure and make. The output of the kernel build is shown only if it fails (PLUMED_BUILD_VERBOSE=1 shows everything), and with PLUMED_RUNTIME_CACHE the kernel is built once and reused for all the python versions.
      • The Python package workflow builds the source distribution and, with cibuildwheel, the wheels for CPython 3.11 to 3.15 (manylinux2014 and macOS), tests the installed wheels with python/test/test_bundled_wheel.py, and publishes them with PyPI Trusted Publishing when a v* tag is pushed (or to TestPyPI when started by hand).
      • The consistency of python/plumed.c is checked with python/compare_plumed_c.sh, which ignores the compressed copies of the strings that cython (>=3.1) generates, since they depend on the python version and on the compression libraries used to run cython.
    • The CI also runs every night on the master branch, and can be started by hand from the Actions tab.
    • A regtest can be marked as long with plumed_long=yes in its config: it then runs only when PLUMED_LONG_TESTS=yes, as in the nightly CI run, and not on pull requests.
    • New CI jobs build all the modules and run the regtests with AddressSanitizer and UndefinedBehaviorSanitizer, with clang without OpenMP (any warning of -Wall -Wextra in PLUMED code fails the job, see .ci/check-warnings), and with --disable-dlopen. The regtests that need dlopen declare plumed_needs=dlopen.
    • CI fails when an example of the manual that worked stops working: the pages with known failures are listed in new-manual/broken-examples.allowed, a list that should only shrink.
    • .ci/audit-inputs.py runs the examples of the manual and variants of them (a keyword removed, a number set to 0 or -1, a list cut to one element) and reports the inputs that crash PLUMED or stop it with an assertion instead of an error message.
