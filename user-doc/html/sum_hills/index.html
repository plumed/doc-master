    Command line tool: sum_hills

    Module cltools
    Description Input
    sum the hills of metadynamics to compute the free energy command line args

    Details

    sum_hills is a tool that sums the Gaussians in a hills file and writes the resulting free energy on a grid.

    This tool is most frequently used after a METAD simulation to sum all the Gaussians in the hills file and output the free energy surface:

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --hillsthe hills files to sum, separated by commas PATHTOMYHILLSFILE
The sum_hills action with label plumed calculates something

    The default name for the output file is fes.dat. It contains, for each point of the grid, the free energy and its derivatives with respect to the variables. The free energy is minus the sum of the Gaussians: with well-tempered metadynamics the heights written in the hills file are already scaled by (where is the bias factor), so that their sum is directly the estimate of minus the free energy. As always, the free energy is defined up to an additive constant; use --mintozero to shift its minimum to zero.

    sum_hills automatically detects the variables in the hills file and their periodicity. A column X of the file is a variable if the file also contains its width (sigma_X, or sigma_X_X for multivariate Gaussians), whatever the name of the variable. If you used flexible hills (multivariate Gaussian kernels), sum_hills understands it from the hills file.

    Choosing the grid

    By default the grid is chosen so as to contain all the Gaussians, with a spacing of about a third of the smallest width. You can instead choose the number of bins:

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --binthe number of bins of the grid, one for each variable 99,99 --hillsthe hills files to sum, separated by commas PATHTOMYHILLSFILE
The sum_hills action with label plumed calculates something

    In the command above the minimum and maximum of the grid are still detected for you. If you want to set them yourself you can do so as shown below:

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --binthe number of bins of the grid, one for each variable 99,99 --minthe lower bounds of the grid, one for each variable; by default they are detected from the hills  --maxthe upper bounds of the grid, one for each variable; by default they are detected from the hills pi,pi --hillsthe hills files to sum, separated by commas PATHTOMYHILLSFILE
The sum_hills action with label plumed calculates something

    You can of course use numbers instead of -pi/pi. --min and --max must be given together. Instead of the number of bins you can give the grid spacing with --spacing, with or without --min and --max. If you give both --bin and --spacing, the larger number of bins is used for each variable.

    Multiple files and multiple walkers

    sum_hills can also accept multiple files:

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --hillsthe hills files to sum, separated by commas PATHTOMYHILLSFILE1,PATHTOMYHILLSFILE2,PATHTOMYHILLSFILE3
The sum_hills action with label plumed calculates something

    The files are integrated one after the other. This does not change the final free energy, but when you use --stride (see below) with the hills files of multiple walkers the intermediate free energies would not follow the simulation. With --sort time the hills of all the files are merged in order of their time (hills with the same time are taken in the order of the files), so that each intermediate free energy contains the hills deposited by all the walkers up to a given time:

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --hillsthe hills files to sum, separated by commas HILLS.0,HILLS.1,HILLS.2 --sorttime or clock: with multiple files (e time --stridewrite the free energy (or histogram) every this number of hills (or points); by default only at the end 300

    With --sort clock the hills are merged in order of the clock field (the wall-clock time at which they were deposited, written with multiple walkers), which is more appropriate when the walkers run at different speeds. Each file should be ordered by the chosen field.

    Integrating out variables

    If you want to integrate out some variables from your free energy surface you can use --idw:

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --hillsthe hills files to sum, separated by commas PATHTOMYHILLSFILE --idwthe variables of the output (default all) t1 --ktthe temperature in energy units, needed with --idw, --histo and --basins 0.6

    With --idw you list the variables that you want in the output free energy surface. All the other variables in the hills file are integrated out, i.e. , where the sum runs over the points of the grid. --kt is the temperature of the system in energy units: be consistent with the units of your hills file, since plumed will not check this for you. If you need more variables you can list them separated by commas:

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --hillsthe hills files to sum, separated by commas PATHTOMYHILLSFILE --idwthe variables of the output (default all) t1,t2 --ktthe temperature in energy units, needed with --idw, --histo and --basins 0.6

    Following the convergence

    With --stride you can write the free energy after each bunch of hills (the stride is a number of hills):

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --stridewrite the free energy (or histogram) every this number of hills (or points); by default only at the end 300 --hillsthe hills files to sum, separated by commas PATHTOMYHILLSFILE

    The output files are then called fes_0.dat, fes_1.dat, etc. (see below), and the last one contains all the hills.

    With --nohistory each output contains only the hills of its own block of hills, instead of all the hills up to that point:

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --stridewrite the free energy (or histogram) every this number of hills (or points); by default only at the end 300 --hillsthe hills files to sum, separated by commas PATHTOMYHILLSFILE --nohistory with --stride, each output contains only the hills (or points) of its own block
The sum_hills action with label plumed calculates something

    In this way you can monitor the bias deposited in blocks of time as a metadynamics simulation goes on: when the bias deposited in a block is constant over the whole domain, the simulation can be considered to be at convergence.

    To check the convergence you can also follow the free-energy difference between basins as the simulation goes on. With --basins you can define two or more basins as boxes, each given by the minimum and the maximum of each variable of the output, with the basins separated by colons. Along a periodic variable a basin can cross the boundary if its minimum is larger than its maximum. For example

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --hillsthe hills files to sum, separated by commas PATHTOMYHILLSFILE --stridewrite the free energy (or histogram) every this number of hills (or points); by default only at the end 500 --ktthe temperature in energy units, needed with --idw, --histo and --basins 2.5 --basinsbasins separated by colons, each given by the minimum and maximum of each output variable (e

    writes, at each output, the time of the last hill read, the number of hills, and the free energy of each basin relative to the first one, computed as over the points of the grid, in the file basins.dat (the name can be set with --outbasins). With --idw the basins are defined on the projected variables. With --histo (see below) the same is done for the free energy from the histogram, in the file histo_basins.dat. A plateau of these differences is a necessary (not sufficient) indication of convergence.

    Time average of the bias

    With standard (not well-tempered) metadynamics the bias does not converge but fluctuates around the free energy. A better estimate is the time average of the bias after an initial transient, which you can obtain with --average:

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --hillsthe hills files to sum, separated by commas PATHTOMYHILLSFILE --averagetime average of the bias from time t0 (t0) or between times t0 and t1 (t0,t1); without t1 the average ends at the last hill read 1000
The sum_hills action with label plumed calculates something

    computes the average of the bias between time 1000 (in the units of the time column of the hills file) and the time of the last hill. This is done by scaling the height of each hill deposited at time after 1000 by , where is the final time. You can also give the final time explicitly, e.g. --average 1000,5000: hills deposited after 5000 are ignored. The same average is useful for well-tempered metadynamics, where it reduces the fluctuations of the estimate of the free energy. Combined with --stride, each output is the average from the initial time up to the last hill read. This is the same average computed by the function hills_time_average of the plumed python module.

    Bias instead of free energy

    If you have run well-tempered metadynamics you can also ask sum_hills to output the negative bias, , instead of the free energy by using --negbias:

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --negbias write minus the bias instead of the free energy (they differ only with well-tempered metadynamics) --hillsthe hills files to sum, separated by commas PATHTOMYHILLSFILE
The sum_hills action with label plumed calculates something

    Here the default output file name is negativebias.dat. If the simulation was not well tempered the bias is minus the free energy, and the output is the same as without --negbias.

    Histograms

    From time to time you might need to use a hills or a colvar file as a set of points from which you want to build a free energy as . You can do this with --histo:

    plumed sum_hillssum the hills of metadynamics to compute the free energy More details --histothe files (hills or colvar) from which a histogram is computed, separated by commas; the points are not reweighted PATHTOMYCOLVARORHILLSFILE --sigmathe widths of the Gaussian kernels of the histogram, one for each variable (needed with --histo) 0.2,0.2 --ktthe temperature in energy units, needed with --idw, --histo and --basins 0.6
The sum_hills action with label plumed calculates something

    The histogram is computed with Gaussian kernels whose widths are given with --sigma, one for each variable, so it is a continuous histogram, and --kt is needed to convert it into a free energy. The default output file is histo.dat. With a hills file the variables are those of the hills; with a colvar file all the columns but time are variables, so you will usually select some of them with --idw (and give one width for each of them). Multiple input files can be given, separated by commas.

    All the points have the same weight: the result is the distribution sampled by the simulation, which is the free energy only if the simulation was not biased. sum_hills does not reweight the points. To compute a free energy from a biased simulation (e.g. from the COLVAR file of a metadynamics simulation) use driver with READ, REWEIGHT_BIAS (or REWEIGHT_METAD), HISTOGRAM and CONVERT_TO_FES, for example
